# GB-85: Immediate Header Presentation, Live Progress Spinners, and Fast Deterministic Suite Release Planning

## Context & Root Cause
When running `outfeed release --all`:
1. Phase 1 ran pre-flight silently without any stdout or progress spinner.
2. Phase 2 (`plan_suite_releases`) called `plan_release` with remote LLM changelog synthesis enabled for every single non-clean repository before printing anything to stdout.
3. For 8 member repositories, this executed 8 sequential remote LLM queries (taking 2.5 minutes) with zero terminal output, making the CLI appear completely frozen.
4. The upfront suite summary table only requires:
   - Current version (from Git tag or Cargo.toml)
   - Unreleased commit counts (from Git rev-parse / log)
   - SemVer bump calculation (from Conventional Commit prefixes)
   - Target version (from SemVer bump)
   - Referenced Storypole tickets (from commit messages)
   All of these operations are 100% deterministic local AST/Git operations that take under 50 milliseconds across the entire workspace.
5. In Phase 3 (`execute_suite_plan` / `release_repo`):
   - In dry-run mode, LLM synthesis was called despite notes never being applied or committed.
   - Initial progress reporting did not clearly label the active changelog evaluation phase.

## Implementation Steps
1. In `outfeed/crates/outfeed-core/src/suite_plan.rs`:
   - Enforce fast deterministic commit evaluation (`no_llm: true`) inside `plan_suite_releases` so Phase 2 finishes in <50ms without network overhead.
2. In `outfeed/crates/outfeed-cli/src/commands/release.rs`:
   - Print the suite release header banner immediately upon invocation.
   - Start live spinner progress on `"suite"` for pre-flight validation.
   - Update spinner progress for suite plan compilation.
   - Complete spinner and render the compact summary table instantly.
   - Wire interactive confirmation prompt `Proceed with release? [y/N]: ` (bypassed with `--yes`, `--dry-run`, or `--json`).
3. In `outfeed/crates/outfeed-core/src/release.rs`:
   - In `release_repo`, bypass remote LLM calls if `opts.dry_run` is set (`let no_llm = opts.no_llm || opts.dry_run;`).
4. Validate with Tier 1 and Tier 2 tests; ensure all files remain <= 250 LOC.
