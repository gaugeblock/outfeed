# Task Plan: GB-124 — Switch Release Verification to cargo-nextest and Make Binary Install Opt-in

> **Task Key:** `GB-124`  
> **Parent Epic:** `GB-121`  
> **Scope:** `outfeed-core,outfeed-cli`  
> **Status:** Planned

---

## 1. Problem Statement
`outfeed-core/src/engine.rs` hardcodes `cargo test --workspace` via standard subprocess, completely bypassing the installed `cargo-nextest` runner. Before running tests, it runs a redundant `cargo check --workspace`. Furthermore, `release_repo` forces a full `cargo install --force` in release mode for every single repository, adding 20–30 minutes of binary compilation during releases.

---

## 2. Technical Blueprint
1. In `outfeed-core/src/engine.rs`:
   * Eliminate the redundant `cargo check --workspace` prior to testing.
   * Detect `cargo-nextest` on PATH:
     * If present: execute `cargo nextest run --workspace` (followed by `cargo test --doc` if doc tests exist).
     * If absent: fallback cleanly to `cargo test --workspace`.
2. In `outfeed-core/src/model/options.rs` & `outfeed-cli/src/args/release.rs`:
   * Invert installation behavior: skip binary compilation into `~/.cargo/bin` by default during `release --all`.
   * Add `--install` flag to explicitly opt in to local binary installations.

---

## 3. Execution Steps
* **Step 1:** Invert install default and add `--install` argument.
* **Step 2:** Wire `cargo-nextest` execution into `engine.rs` and drop redundant `cargo check`.
* **Step 3:** Tier 2 verification (`cargo nextest run -p outfeed-core`).
