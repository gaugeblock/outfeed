# GB-92: Roll back modified Cargo.lock when Tier 4 verification fails during outfeed release

## Context & Root Cause
In `outfeed-core` (`crates/outfeed-core/src/engine.rs`), Step 2 runs `cargo check --workspace` which synchronizes `Cargo.lock` to the newly bumped version.
If Step 3 (Tier 4 verification `cargo test --workspace`) fails:
`outfeed` calls `rollback_manifest_diffs(repo_dir, &plan.manifest_diffs)` which restores `Cargo.toml` and `CHANGELOG.md`.
However, `Cargo.lock` is not rolled back. This leaves `Cargo.lock` dirty in the working tree, blocking all subsequent release attempts with `Working tree is dirty: M Cargo.lock`.

## Implementation Steps
1. In `outfeed/crates/outfeed-core/src/engine.rs`:
   - When rolling back manifest diffs after a failed verification, also revert `Cargo.lock` if it exists in the repository root (e.g. via `git checkout -- Cargo.lock` or restoring its original state).
2. Add a helper function or integrate into rollback logic to ensure working tree cleanliness on aborted release.
3. Verify with unit tests in `outfeed-core`.
4. Commit atomically: `fix(outfeed-core): roll back Cargo.lock on release verification failure`.
