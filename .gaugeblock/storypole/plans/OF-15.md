# GB-78: Capture Cargo Test Verification Output, Fix Misleading Step Labels, and Add --no-verify to Outfeed Release

## Problem
1. **Compilation/Test Output Leaking:** In `apply_release`, `cargo test --workspace` was invoked using `.status()`, which connected directly to stdout/stderr. Thousands of compiler and test output lines streamed to the terminal while `indicatif` progress spinners were ticking, corrupting cursor positions, duplicating progress bars, and scrambling the terminal UI.
2. **Misleading Step Information:** `release_repo` prematurely emitted `committing and tagging v...` before invoking `apply_release`. Inside `apply_release`, long-running test suites executed for minutes while the UI misleadingly claimed it was committing and tagging.
3. **Missing `--no-verify` Flag:** `outfeed apply` supported `--no-verify`, but `outfeed release` did not expose `--no-verify` or allow skipping the verification test suite.

## Solution
1. Use `run_captured(&mut test_cmd)` for `cargo test --workspace` in `engine.rs` so stdout/stderr are cleanly captured in memory.
2. Implement `apply_release_with_progress` taking `&dyn ProgressReporter` and reporting discrete, accurate phases:
   - `updating manifests & changelog...`
   - `synchronizing Cargo.lock...`
   - `running verification tests (cargo test)...`
   - `certifying release in Storypole...`
   - `committing and tagging v{target_version}...`
3. Add `--no-verify` to `ReleaseArgs` and `no_verify: bool` in `ReleaseOpts`.
4. Ensure all files remain strictly under 250 LOC and Tier 2/Tier 3 gates pass.
