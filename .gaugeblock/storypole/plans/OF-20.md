# GB-100: Add disk space pre-flight check and inter-repo cache hygiene to outfeed release

## Context & Problem Statement
During macro suite releases (`outfeed release --all`), up to 10 member repositories compile, run Tier 4 test suites, install binaries, and run `cargo publish --dry-run` sequentially. All of these compilation steps write artifacts into the shared workspace `target/` directory.

Because debug artifacts, object files (`.rlib`, `.rmeta`), and test binaries accumulate across repositories, `target/` can grow to 15–25+ GB. On storage-constrained machines (such as environments with under 15 GB available), a suite release fails midway with `No space left on device` (OS error 28). This leaves the workspace in a partially-released state where earlier repositories were bumped, tagged, or pushed while subsequent repositories remain unreleased.

## Invariants & Design Decisions

### 1. Pre-flight Disk Space Audit
- Query available filesystem space for `workspace_root` using POSIX `df -P -k <path>` (supported on macOS, Linux, BSD) or safe fallback.
- Enforce minimum headroom requirements:
  - Default for single repo release: **2.5 GB**.
  - Default for suite release (`--all` with inter-repo clean enabled): **4.0 GB**.
  - Default for suite release (`--all` with inter-repo clean disabled): **20.0 GB**.
- If free space is below the required threshold, abort in pre-flight with `OutfeedError::InsufficientDiskSpace` before modifying manifests or tags.
- Support CLI overrides `--min-disk-gb <N>` and `--skip-disk-check`.

### 2. Inter-Repo Cache Hygiene
- In `execute_suite_plan`, after each repository completes its full release lifecycle (`cargo test` -> manifest bump -> commit & tag -> `cargo install` -> `cargo publish`), clean disposable intermediate artifacts.
- Target clean specifically targets:
  - `target/debug`: intermediate object files and test executables.
  - `target/package`: dry-run crate tarballs.
- Preserves installed binaries (`cargo install` copies binaries directly into `~/.cargo/bin`).
- Enabled by default during suite release (`--all`); configurable via `--no-clean-between-repos`.
- Reports reclaimed bytes via `ProgressReporter`.

### 3. File Size Invariant (Law 1: < 250 LOC)
- Implement disk space inspection in a new dedicated module `outfeed-core/src/disk_space.rs` to avoid exceeding the 250-line limit in `clean.rs` or `suite_check.rs`.

## Execution Plan & Verification Steps
1. Create `outfeed/crates/outfeed-core/src/disk_space.rs` with `get_available_disk_space` and `check_disk_space_headroom`.
2. Add `InsufficientDiskSpace` variant to `outfeed/crates/outfeed-core/src/error.rs`.
3. Add `clean_between_repos`, `min_disk_bytes`, and `skip_disk_check` to `ReleaseOpts` in `outfeed-core` and CLI args in `outfeed-cli`.
4. Integrate disk space check into `check_suite_preflight` in `outfeed-core/src/suite_check.rs`.
5. Integrate inter-repo clean into `execute_suite_plan` in `outfeed-core/src/release.rs`.
6. Run Tier 1 and Tier 2 verifications: `cargo fmt`, `cargo clippy`, and `cargo nextest run -p outfeed-core -p outfeed-cli`.
