# GB-83: Add --yes Flag and Concurrency Controls to outfeed release CLI

## Problem
1. **Interactive Prompt Bypass for Automated Environments:**
   With the introduction of the confirmation gate in the 3-phase release pipeline, automated CI scripts and agent harness runs need a non-interactive bypass flag (`--yes` / `-y`).
2. **Missing Workstation Concurrency Control:**
   Power users and high-core workstations should be able to specify concurrency levels via `--jobs` / `-j` when executing releases, while defaulting safely to sequential execution (`jobs = 1`) on resource-constrained laptops.

## Solution
1. **Update `ReleaseArgs` in `outfeed-cli`:**
   - Add `#[arg(short = 'y', long = "yes", help = "Automatically confirm release plan without prompting")] pub yes: bool`.
   - Add `#[arg(short = 'j', long = "jobs", default_value = "1", help = "Maximum concurrent release jobs (default: 1)")] pub jobs: usize`.
2. **Wire Confirmation Gate in CLI Handler:**
   - In `outfeed-cli::commands::release`:
     - Render the Plan Table.
     - If `--dry-run`: run simulated execution automatically.
     - If zero releases: print status and return Ok(()).
     - If not `--yes` and not `--json`: prompt `Proceed with release? [y/N]` using `dialoguer` or `std::io::stdin`.
     - Dispatch to `execute_suite_releases` passing `jobs`.

## Step Breakdown
- Step 1: Add `--yes` and `--jobs` flags to `ReleaseArgs` in `outfeed-cli` (Gate: `cargo check -p outfeed-cli`)
- Step 2: Implement confirmation prompt and wire CLI to 3-phase pipeline (Gate: `cargo test -p outfeed-cli`)
- Step 3: Run Tier 2 verification and dogfood `outfeed release --all --dry-run` (Gate: `cargo nextest run --workspace`)
