# GB-73: Orchestrate meta-harness suite release and suite.lock generation in outfeed

> **Status:** Ready  
> **Target Scope:** `outfeed-core`, `outfeed-cli`  
> **Key Invariants:**  
> 1. Hard 250 LOC rule on all `.rs` files.  
> 2. Zero-panic error handling with strongly typed errors via `thiserror`.  
> 3. Enforces clean porcelain tree checks before release tagging.  
> 4. Deterministic snapshot reproducibility via `suite.lock`.  

---

## 1. Overview & Objectives

While `outfeed release --all` (GB-72) iterates across the 10 member repositories to plan, apply, install, push, and publish individual crates, the meta-harness itself (`gaugeblock/gaugeblock`) requires an overarching release coordinator:

`outfeed release suite` (or `outfeed release --suite`):
1. Runs pre-flight verification across the workspace.
2. Gathers the latest verified tags, versions, and commit SHAs across all 10 member repositories.
3. Generates the canonical `suite.lock` manifest.
4. Verifies/updates root `CHANGELOG.md` with suite milestone highlights.
5. Commits `suite.lock` and `CHANGELOG.md` to `main`.
6. Creates the annotated git tag `suite-v<version>` (e.g., `suite-v0.1.0-beta.2`).
7. Pushes the release commit and tag to `origin` (`gaugeblock/gaugeblock`).
8. Generates a GitHub Release with changelog release notes.

---

## 2. CLI Interface & Flags

```bash
# Preview suite release without side effects
outfeed release suite --dry-run

# Run full suite release with explicit target version
outfeed release suite --version 0.1.0-beta.3

# Run suite release skipping push
outfeed release suite --skip-push
```

---

## 3. Architecture & Verification Gates

1. Core module: `crates/outfeed-core/src/suite_release.rs` (<250 LOC).
2. Manifest generation: writes TOML formatted `suite.lock` at workspace root.
3. Tier 2 gate: `cargo clippy -p outfeed-core -p outfeed-cli --all-targets -- -D warnings`, `cargo test -p outfeed-core`.
4. Dogfooding: `outfeed release suite --dry-run`.
