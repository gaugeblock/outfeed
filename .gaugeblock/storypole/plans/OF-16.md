# GB-82: Implement Check -> Plan -> Execute 3-Phase Suite Release Pipeline in outfeed-core

## Problem
1. **Blind Sequential Execution:**
   `outfeed release --all` sequentially iterates through repos without an upfront plan, giving the operator zero visibility into which repos will be bumped, their target versions, or which are clean.
2. **Late Failures on Dirty Repos:**
   If repository 8 has uncommitted changes or is on a feature branch, the release pipeline executes for minutes on repositories 1–7 before crashing on repository 8, leaving the workspace in a half-released, dirty state.
3. **No Upfront Confirmation Gate:**
   Operators have no opportunity to inspect proposed versions or abort before irreversible tag creations, installations, and pushes occur.

## Solution
1. **Phase 1: Pre-flight Check (`check_suite_preflight`):**
   - Concurrently audit all 10 repositories (`main` branch check, clean working tree, remote tracking sync).
   - Strict Fail-Fast: Abort upfront with a diagnostic status table if any repository fails.
2. **Phase 2: Suite Release Plan (`plan_suite_releases`):**
   - Concurrently analyze git commits and Storypole tasks across all member repos using `futures::future::join_all`.
   - Calculate semver bumps and render the upfront **Compact Summary Table**:
     `REPOSITORY | CURRENT | TARGET | ACTION | COMMITS | TASKS`.
   - Auto-Exit Clean: If 0 repos need releases, print status and exit code 0.
3. **Phase 3: Topological Execution (`execute_suite_releases`):**
   - Execute releases strictly in topological dependency order.
   - Enforce concurrency control (`jobs = 1` by default for CPU/RAM safety on laptops).
   - Use captured verification and granular step progress.

## Step Breakdown
- Step 1: Implement `check_suite_preflight` in `outfeed-core::suite_check` (Gate: `cargo check -p outfeed-core`)
- Step 2: Implement `plan_suite_releases` and `format_suite_plan_table` in `outfeed-core::suite_plan` (Gate: `cargo check -p outfeed-core`)
- Step 3: Implement `execute_suite_releases` and refactor `release_all` in `outfeed-core::release` (Gate: `cargo test -p outfeed-core`)
- Step 4: Tier 2 verification in `outfeed-core` (Gate: `cargo nextest run -p outfeed-core`)
