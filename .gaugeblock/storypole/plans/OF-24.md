# Task Plan: GB-122 — Implement Adaptive Disk Space Headroom Guard and Cache Retention in outfeed

> **Task Key:** `GB-122`

> **Scope:** `outfeed-core`  
> **Status:** Verified (Tier 3 gate green on `dd42b57`)

---

## 1. Problem Statement
`clean_between_repos` currently defaults to `true`, wiping `target/debug` after every released repository. This forces all 10 tools to recompile `syn`, `tokio`, `serde`, and uncached proc-macros from scratch, adding 30–50 minutes of pure CPU churn. If disabled, `outfeed` artificially demanded 20.0 GB of free disk, failing on systems with 12 GB free despite the shared target directory plateauing at only ~5.0 GB.

---

## 2. Technical Blueprint
1. In `outfeed-core/src/model/options.rs`:
   * Change `ReleaseOpts.clean_between_repos` default to `false`.
2. In `outfeed-core/src/suite_check.rs`:
   * Change required headroom threshold to `DEFAULT_MIN_SUITE_DISK_BYTES` (4.0 GB) regardless of `clean_between_repos`.
3. In `outfeed-core/src/suite_exec.rs`:
   * Add continuous `get_available_disk_space()` monitoring before/after every repository release.
   * If available disk `< 3.5 GB`: trigger adaptive surgical pruning of test binaries in `target/debug/deps` using `prune_workspace()`.
   * If available disk `< 2.0 GB`: trigger emergency target clean.
4. In `.cargo/config.toml`:
   * Add `[env] SCCACHE_CACHE_SIZE = "15G"` to prevent LRU cache eviction thrashing.

## 4. Implementation Notes (as executed)

* **Guard module:** the adaptive guard lives in `outfeed-core/src/headroom/` (`mod.rs` + `tests.rs`)
  rather than inline in `suite_exec.rs`, keeping both files well under the 250-line hard limit.
  `suite_exec::guard_disk_headroom` measures free space immediately **before** each repository
  release and again **after** its build/test wave.
* **Surgical pruning intentionally does not call `prune_workspace()`.** `prune_workspace` deletes
  every entry in `target/debug/deps` older than the cutoff, so `keep_days = 0` would wipe rlibs,
  rmeta files and proc-macro libraries — exactly the artifacts cache retention exists to preserve.
  `headroom::prune_test_binaries` therefore sweeps only extension-less executables (test/example
  binaries) and `headroom::clean_target_package` drops `target/package` staging.
* **Thresholds:** `ADAPTIVE_PRUNE_DISK_THRESHOLD_BYTES` (3.5 GB) and
  `EMERGENCY_CLEAN_DISK_THRESHOLD_BYTES` (2.0 GB) live in `disk_space.rs`; pre-flight always
  demands `DEFAULT_MIN_SUITE_DISK_BYTES` (4.0 GB). `DEFAULT_MIN_SUITE_NO_CLEAN_DISK_BYTES` is
  retained only as a documented legacy export to avoid a breaking API removal.
* **CLI:** `--no-clean-between-repos` is replaced by the opt-in `--clean-between-repos`, since
  retention is now the default.
* **sccache:** `SCCACHE_CACHE_SIZE = "15G"` is set in the meta-harness root `.cargo/config.toml`
  (the file that owns `rustc-wrapper = "sccache"` for all 11 workspace targets).
